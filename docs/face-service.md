# Face service setup

The service uses InsightFace 0.7.3’s FaceAnalysis API with ONNX Runtime on CPU, extracting normalized 512-dimensional ArcFace embeddings. There are no demographic attributes, stored camera photos, or background face tracking.

## Models and liveness

InsightFace library code and supplied pretrained model weights have different licenses. The project’s [official Python README](https://github.com/deepinsight/insightface/blob/master/python-package/README.md) and [licensing site](https://www.insightface.ai/) describe the pretrained weights as non-commercial research models. Obtain an appropriate model license or independently suitable weights before operational deployment. This repository includes no weights and never automatically downloads them.

Put the compatible detection and recognition ONNX files here:

```text
data/models/models/buffalo_l/
  det_10g.onnx
  w600k_r50.onnx
```

The complete compatible buffalo_l pack also works. The directory is mounted as `/models`; the repeated `models` segment follows InsightFace’s layout. Startup fingerprints the model files, so templates from different models are never silently compared. Re-enroll employees when changing the model pack.

**No liveness implementation is included.** A photo or replay attack has not been mitigated. `/recognize` returns 503 unless `ALLOW_UNVERIFIED_LIVENESS=true`, which is solely for supervised research demonstrations. Production recognition requires an actual anti-spoofing implementation and testing; changing the flag does not provide liveness.

## Docker alongside the local Node app

Install Docker, keep the `.env` generated by `npm run dev`, and run:

```powershell
docker compose -f compose.yaml -f compose.face-local.yaml --profile face up -d --build face
```

The service listens on `127.0.0.1:8000`. The API and face service must use the same `AI_SERVICE_KEY`. For a supervised demonstration only, set the research flag in `.env` and recreate the face container. Check **Administration** for model readiness.

## Native Python alternative

Use Python 3.11. InsightFace 0.7.3 may require a C++ build toolchain on Windows; Docker avoids that host dependency.

```powershell
cd services/face
python -m venv .venv
.venv\Scripts\python -m pip install -r requirements.txt
$env:AI_SERVICE_KEY = '<same value as root .env>'
$env:MODEL_ROOT = (Resolve-Path ..\..\data\models).Path
# Optional supervised research only:
# $env:ALLOW_UNVERIFIED_LIVENESS = 'true'
.venv\Scripts\python -m uvicorn app.main:app --host 127.0.0.1 --port 8000 --no-access-log
```

The service requires its private `X-Service-Key` header on every endpoint and should never be publicly exposed. Capture requests accept one JPEG/PNG, capped in encoded size, pixel dimensions, and minimum face size. API timeouts and error messages direct employees to HR when inference is unavailable. Images and plaintext templates are processed in memory, and access logs are disabled.

Matching uses cosine similarity with a default threshold of `0.55` and minimum top-two margin of `0.08`. These are development starting values, **not measured accuracy guarantees**. Calibrate `MATCH_THRESHOLD` and `MATCH_MARGIN` using appropriately authorized local evaluations, including false matches, false non-matches, lighting, angles, accessibility needs, and replay attacks. Keep the same model and normalization at enrollment and attendance capture.
